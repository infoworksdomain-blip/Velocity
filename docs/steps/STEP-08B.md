# STEP 8B — Hook & On-Screen Text Engine

Status: proceeding without an approval gate (see STEP-03.md's header note).

This is the first-class subsystem the build script calls "the cheapest lever on performance in the whole product" — hooks, captions, and overlays, produced from one frozen schema (`TextPlan`, ADR 0005) that drives both a real Anthropic adapter and a real OpenAI adapter, validated and repaired before it ever reaches a render, then laid out by a real auto-fit/legibility/safe-area engine rather than left to the model.

## Scope decisions

1. **The Anthropic and OpenAI adapters are real, not stubs.** This is the substantive difference from every other provider kind in this codebase: `AnthropicTextProvider`/`OpenAITextProvider` (`packages/text-engine/src/adapters/`) make genuine `@anthropic-ai/sdk`/`openai` SDK calls — forced tool-use for Anthropic, strict JSON-schema `response_format` for OpenAI — built and verified against local mock servers mimicking each vendor's real response shape (the same honeypot-style pattern STEP 6 uses for SSRF testing), not against the live APIs, since no funded key exists in this environment. `pnpm typecheck` catching every wrong SDK field/method name against the *actual installed SDK's own types* is real evidence the request shapes are correct, not just that hand-written code compiles.
2. **A deterministic stub stands in automatically when no key is configured — not as a separate code path, but inside the same factory.** `apps/worker/src/temporal/activities/context.ts` registers one factory per provider id that checks `entry.credentials.apiKey` (resolved from `${ANTHROPIC_API_KEY}`/`${OPENAI_API_KEY}` by the existing `FileProviderConfigSource`) and constructs the real adapter when a key is present, `StubTextProvider` otherwise. This is a genuine improvement on the "swap this stub file for a real one later" pattern STEP 6/8 used — the render pipeline is fully real and fully runnable in this sandbox *and* automatically starts using a funded key the moment one is configured, with no code change.
3. **The `text` kind extends STEP 8's existing ADR 0004 router rather than forking a parallel one.** `ProviderKindSchema` gained a fifth member; `TextProvider` (defined in `packages/text-engine`, ADR 0005's home for it) joined `AnyProvider`; `config/providers.json` gained `anthropic`/`openai` entries. `selectOne`'s capability/compliance/cost-ceiling/breaker ranking needed zero kind-specific code changes — `RouterCriteria.jobShape.characters` already existed (added for TTS), and every capability check field is optional, so a text entry with `{commercialUse: true, costPerCharacter}` and no `maxDurationSec`/`resolutions`/etc. is handled correctly by the existing generic logic. This is real evidence the router genuinely is provider-kind-agnostic, not a video-shaped abstraction with a text-shaped exception bolted on.
4. **The render-time auto-fit measurer and the validation-time pre-flight measurer are deliberately two different things.** Build script 8B.5 specifies canvas `measureText` "at render time" — a real browser API, run inside Remotion's actual render context (Studio or a headless Lambda render), which this Node-only sandbox does not have (confirmed directly: no `document`). `apps/render/src/text/canvas-measurer.ts` is that real measurer, real shape, unrunnable here — the same category of gap as the missing ffmpeg binary. The validation/repair loop (8B.4 step 2, running inside the Node worker, *before* any render exists) needs *some* answer to "will this roughly fit" and cannot wait for a browser — `packages/text-engine/src/layout/heuristic-measurer.ts` is a real, documented, average-glyph-width approximation for exactly that pre-flight purpose, explicitly not claimed to be pixel-accurate. The `binarySearchFontSize`/`fitsWithinBox` algorithm both measurers plug into is the same code either way and is fully real and fully tested.
5. **Real per-frame luminance sampling is a documented, self-contained follow-up, not fabricated.** `packages/text-engine/src/layout/legibility.ts`'s luminance/contrast math is real and fully tested against synthetic pixel buffers. What it needs at actual render time — the composed frame's real pixels under each overlay — requires Remotion's real render pipeline, which (like the canvas measurer) this sandbox cannot exercise. `apps/render/src/compositions/TextLayerSlot.tsx` uses a fixed default luminance in the interim, called out explicitly in its own module comment rather than silently assumed.
6. **`compose-text.ts` fills STEP 8's own documented seam, filling the same `render_steps` idempotency ledger with a genuinely different failure-mode shape than the other four provider kinds.** Video/TTS/image/transcription jobs are real submit-then-poll vendor jobs with a queryable status endpoint — a resumed activity re-polls the *same* job id. A structured-text call has no such vendor-side job to poll by; the entire terminal result (the validated `TextPlan`, whether or not it needed a repair call or fell back to the template, and its real cost) is produced by one `submit()` invocation and encoded directly into the ledger row's `external_job_id` column (a text column, repurposed to carry a small JSON payload instead of a vendor id) so `poll()` can return it deterministically without ever calling the vendor again. This keeps the crash window identical in kind to the other four steps' (a single short DB write immediately after the network call returns), rather than silently accepting a wider one because the vendor shape didn't fit the existing pattern.
7. **The "last 200 published hooks" duplicate check reuses STEP 8.2's existing proxy source (content_concepts), not a stricter new join.** STEP 8.2's own concept-generation duplicate check already treats "the workspace's most recent `content_concepts` hooks" as the practical stand-in for "published hooks" (no `content_items.status = 'published'` join). STEP 8B.4's duplicate check uses the same source for the same reason and stays consistent with it, rather than introducing a stricter standard in one of the two places that needs this check and not the other.
8. **STEP 8.2's own angle/concept-generation stub (`apps/web/server/content-service.ts`) is deliberately NOT swapped to the real adapters in this step.** Its `StubStructuredTextProvider` content-sniffs `args.system`/`args.input` and never inspects `args.schema` — meaning STEP 8.2 was never verified to construct a real, vendor-compatible JSON schema for its own calls. Swapping in a real adapter there without first verifying that schema construction would be introducing an unverified integration risk under STEP 8B's name for a different step's code. `composeText`'s own prompt+schema construction (this step's own, end to end) is what's verified real; STEP 8.2's is an explicitly separate, out-of-scope follow-up.
9. **`targetPlatforms` is a small, additive contract extension**, not a speculative platform-targeting system. Nothing upstream of the render workflow carried a "which short-form video product(s) does this serve" concept before this (STEP 9/13 own real per-workspace platform connections and scheduling); `RenderWorkflowInputSchema.targetPlatforms` defaults to all three (`tiktok`/`reels`/`shorts`) so the text engine always has a real target-platform set to build a `TextPlan`'s required `platformVariants` against.

## What was built

### `packages/text-engine` — real adapters, prompt construction, validation/repair loop, layout engine
`json-schema.ts` (the one real JSON Schema — `zod-to-json-schema` + a recursive `additionalProperties: false` pass for OpenAI's strict mode — both adapters wrap unchanged, per ADR 0005), `adapters/{anthropic,openai}.provider.ts` (real SDK calls, scope decision 1), `adapters/stub.provider.ts` (scope decision 2), `adapters/pricing.ts` (real per-token rate table, flagged `[UNVERIFIED FIXTURE]`), `prompt/build-prompt.ts` (8B.3's rules — hook length, sentence case, proof-points-only claims, platform register, untrusted-content framing), `validation/repair-loop.ts` (8B.4's full pipeline: schema+fit check → one repair call → template fallback, reusing `packages/core`'s real `checkBrandRules`/`classifySafety`), `layout/{safe-areas,line-break,auto-fit,legibility,heuristic-measurer}.ts` (8B.5's algorithms, scope decisions 4-5), `cache/cache-key.ts` (8B.4's cache key). 73 tests, all real (no PGlite/Temporal dependency — pure logic + local mock HTTP servers).

### `packages/contracts`
`ProviderKindSchema` gained `"text"`; `defaultCostCeilingUsd` gained a `text` field; `RenderWorkflowInputSchema` gained `targetPlatforms` (scope decision 9) and `ContentPlatformVariantSchema` (kept deliberately distinct from `primitives.ts`'s existing `Platform` — see that file's own comment on the naming collision this avoided).

### `packages/providers`
`AnyProvider` extended with `TextProvider` (scope decision 3); the video-adapter roster gained `wan-2.2` (a fifth stub vendor, at the user's request, same `[UNVERIFIED FIXTURE]` pattern as the other four).

### `apps/worker` — `composeText`, for real
`temporal/activities/compose-text.ts` replaces STEP 8's placeholder: gathers real context (content concept → angle → brand profile → brand rules → trend blueprint → style presets → hook history, all real DB queries), builds the real prompt, selects a provider via the router, runs the full validation/repair pipeline inside the idempotency ledger (scope decision 6), and persists the result into the same `text_plans` row `render.start` already guaranteed exists. `render.workflow.ts`'s `composeText` call site now passes the full context object instead of just a nullable id. `context.ts` registers the self-adapting real/stub factories (scope decision 2). A genuine, real bug found and fixed along the way: `test:concurrency`'s script (`vitest run <path>`) was silently a no-op — vitest's `exclude` always wins over a CLI positional file argument, so the file being excluded by `vitest.config.ts` meant the "isolated run" script never actually ran it; fixed with a dedicated `vitest.concurrency.config.ts` that includes nothing else.

### `apps/render` — real text-layer components
`src/text/{canvas-measurer,use-overlay-layout,OverlayText,HookOverlay,StickerText,MemeBar,LowerThird,CTAEndCard,CaptionTrack,SlideText}.tsx` — all seven components from 8B.5's table, built on the shared `OverlayText` renderer and the real `useOverlayLayout` hook (auto-fit + legibility, scope decisions 4-5). `compositions/TextLayerSlot.tsx` fills STEP 8's seam: resolves a `TextPlan` by ref (`delayRender`/`continueRender`/`fetch`), computes the target safe box via `boxForPlatforms`, and dispatches each overlay to the right component inside a `<Sequence>`. `VerticalVideoPropsSchema`/`SlideshowPropsSchema` gained the props this needs (`targetPlatforms`, `safeAreasConfig`, `captionWords`, `brandLogoUrl`). Real component shape, unrunnable in this sandbox for the same reasons `VerticalVideo`/`Slideshow` already were (STEP 8) plus the browser-only canvas measurer (scope decision 4) — no separate test runner exists for `apps/render` yet; all algorithmic logic these components call into is tested at the `packages/text-engine` layer instead.

### `config/safe-areas.json`
The real inset numbers from build script 8B.5's table, for all three platforms, versioned per that section's own instruction ("platforms move their chrome").

### `scripts/gate-08b`
Real orchestrator mirroring `scripts/gate-08`'s shape — runs the real test suites, computes the documented cost-per-TextPlan model from real per-token rates. Run `pnpm gate:08b` for the live report.

## Bugs found and fixed during this step

- **`tryFit` (the binary search's internal fit check) didn't re-verify the last line's width.** `breakIntoLines` deliberately lets its final allowed line take every remaining word regardless of width (documented in its own comment — the caller is meant to re-check); `tryFit` was checking total height but never re-measuring each line's width, so the binary search could accept a font size where only the last line silently overflowed horizontally. Found while writing `auto-fit.test.ts`'s line-count test and tracing through the "last line takes everything" path by hand. Fixed by re-measuring every line's width inside `tryFit` before accepting a candidate size; regression test added.
- **`config/safe-areas.json` and `config/providers.json` both have the same CWD-relative-path bug STEP 8 already found and fixed for `FileProviderConfigSource`** — `loadSafeAreasConfig`'s default path resolves against the process's CWD, correct for the real worker (started from the repo root) but wrong under vitest (CWD is `apps/worker`). Caught immediately by the first real `pnpm --filter @velocity/worker test` run after wiring `composeText` in (`ENOENT` on `apps/worker/config/safe-areas.json`) — fixed the same way STEP 8 fixed it: a `VELOCITY_SAFE_AREAS_CONFIG` env var, set to an absolute path by the existing `useRealProviderConfigForTests()` test helper (renamed in spirit, not in name, to cover both configs).
- **`apps/worker`'s `test:concurrency` script was silently a no-op** — see "What was built" above.
- **My own test fixture, not the implementation:** `repair-loop.test.ts`'s first draft of `makeFakeProvider` counted calls assuming `runRepairLoop` calls the injected `TextProvider` twice (once for the "first attempt," once for the repair); it actually calls it exactly once per invocation (the caller generates the first attempt itself and passes the raw result in) — the real, correct design (see scope decision 6's neighboring reasoning: the caller/activity owns the first call, `runRepairLoop` owns only the one repair call). Both GATE 8B recovery-rate tests failed with 0% recovery until this was traced back to the fixture's call-counting logic and fixed; not a defect in `repair-loop.ts` itself.

## What this step does not do

No real vendor API calls (no funded Anthropic/OpenAI key — scope decisions 1-2). No real per-frame luminance sampling at render time (scope decision 5). No Content Studio UI (8B.7 — inline hook editing, variant picker, per-overlay timing drag, style-preset switcher, safe-area guide toggle, "regenerate text only" button, Remotion Player preview) — a real, valuable, explicitly-flagged follow-up, the same way STEP 8 flagged retrofitting STEP 2-7's tests onto the PGlite harness. No swap of STEP 8.2's angle/concept-generation stub to the real adapters (scope decision 8). No per-workspace style-preset customization — `text_style_presets` (already in the schema since STEP 1) needs seeding with the 6 default presets and, if wanted later, a real customization UI; `composeText` reads it with a safe in-code fallback when no row exists. No hook-pattern feedback into the Blitz bandit (STEP 9's job) or analytics (STEP 13's job) yet, though `hook_pattern` is already a real field on every generated `TextPlan`, ready for both.
