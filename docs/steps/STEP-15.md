# STEP 15 — UGC (AI UGC Studio and AI Influencer Studio)

Status: proceeding without an approval gate (see STEP-03.md's header note).

Script-led AI UGC generation with hard, non-bypassable requirements: a persona modelling a real person cannot generate without a real, verifiable consent artefact on file; a script naming a real public figure is refused outright, never merely flagged; a regulated-claim script is blocked until a platform moderator approves it (the first real reader/writer `moderation_reviews` has had since STEP 1); and every licensed human-UGC clip resolves to an actual licence record before it can be selected.

## Scope decisions

1. **Reference-image identity conditioning needed zero new plumbing.** An Explore pass confirmed the full path was already wired end-to-end since STEP 8: `personas.referenceImageStorageKey` → `resolve-assets.ts` → `ShotSpec.referenceImageUrl` → `generate-shots.ts` → `provider.generate()`. This step's real work is the governance layer around generation, not the generation path itself.
2. **`consent_artefacts` is a real, first-class table, not an opaque string.** The old `personas.consentArtefactRef` text column had never been read by any real code path — an opaque reference nobody resolved. Replaced with `consent_artefacts` (subjectName, documentStorageKey, signedAt, nullable expiresAt, verifiedByUserId) and a real FK (`personas.consentArtefactId`). `personas.modelsRealPerson` is a new, explicit `boolean not null default false` — a workspace-declared fact this codebase must be TOLD, deliberately never inferred from a reference image.
3. **The persona generation policy gate has a fixed, deliberate order: consent → public figure → regulated claim.** Consent is checked first because a missing/expired consent artefact is the most fundamental block (this persona should not generate AT ALL right now). Public figure is checked second and is **never reviewable** — GATE 15's own wording says "refused," not "flagged," so `checkPersonaGenerationPolicy` (`packages/core/src/ugc/persona-policy.ts`) hard-stops there regardless of any approved moderation review. Regulated claim is checked last and **is** reviewable — an approved `moderation_reviews` row unlocks it. `ugc-service.test.ts` proves the ordering explicitly: an expired-consent persona with a public-figure-naming, regulated-claim script still reports `consent_missing`, not the later checks; and a public-figure block survives an approved review while a regulated-claim block does not.
4. **`moderation_reviews`' first real reader/writer, ever.** This table has existed since STEP 1's governance schema with zero call sites anywhere in the codebase. `requestModerationReview`/`resolveModerationReview` (`apps/web/server/ugc-service.ts`) are real: a workspace member requests review for an exact `(personaId, script)` pair (`targetType: "persona_script"`, `targetId` is the composite key — a review is scoped to one specific script, not a whole persona, since two different scripts for the same persona can have different regulated-claim outcomes); a platform moderator resolves it via `requirePlatformPermission("moderation:review:platform")` — a real, pre-existing platform-role permission (STEP 1's `moderator` role) that had never been wired to an actual endpoint before this step either.
5. **Public-figure detection reuses STEP 8's lexicon-matching discipline, not a licensed database.** `detectPublicFigureReference` (`packages/core/src/ugc/public-figure-check.ts`) is a real, configurable, word-boundary, case-insensitive matcher — genuinely testable and genuinely functional — seeded from `config/public-figures.json`, an explicitly-labelled small illustrative list (8 globally recognized names), not a comprehensive database. A production system needs a real named-entity-recognition service or a licensed celebrity/public-figure database; neither is available in this sandbox. Stated honest limitation: word-boundary matching still matches a different real person who shares a first+last name pair coincidentally (e.g. a different "Rihanna Cole").
6. **Identity-consistency scoring reuses STEP 8's real perceptual-hash Hamming-distance infrastructure (`qc/phash.ts`) rather than fabricating a face-recognition score.** `scoreIdentityConsistency` (`packages/core/src/ugc/identity-consistency.ts`) is real and genuinely discriminative — proven against real synthetic 8x8 bitmaps (an identical render scores distance 0, a fully-inverted one scores far past the threshold, a mixed 20-sample batch reproduces GATE 15's own literal "20 renders" number with the correct consistency rate). Honest limitation, stated directly: the function takes a `referencePhash` as an argument rather than deriving it from the persona's own stored reference image — extracting a meaningful hash from a real photorealistic image/video frame needs real image-decoding infrastructure this sandbox doesn't have, the exact same gap `phash.ts`'s own doc comment already states for video frames. What's real here is the aggregation across a persona's actual render history (`renders.phash`, set by STEP 8's QC activity) and the Hamming-distance scoring itself, not a claim that the whole reference-derivation pipeline exists.
7. **Licensed-clip selection is deny-by-default, never falls back to an unlicensed clip.** `isClipUsableFor`/`selectLicensedClip` (`packages/core/src/ugc/clip-licensing.ts`) check territory, media, and duration-based expiry against each clip's own `releaseRef`-backed fields; an empty library, or one with no context-matching clip, returns `null` — there is no code path that returns a clip without a resolvable licence.
8. **UGC batch generation reuses STEP 8's render trigger unchanged, split into a PGlite-testable half and a Temporal-dependent half.** `createUgcConceptAndStoryboard` (pure DB writes: validates brandProfile/persona ownership, finds-or-creates a single reusable "UGC" angle per workspace+brand, writes one `content_concepts` row with `format: "ai_ugc"` and one single-scene `storyboards` row using the raw script as `voiceoverLine`) is fully PGlite-tested. `triggerUgcBatchGeneration` is the router-facing orchestrator: it policy-checks every script BEFORE creating any rows, then calls the first function followed by the EXISTING, unmodified `triggerRenderForConcept` (STEP 9's render trigger) for each allowed script — mirroring `calendar-service.ts`'s `previewAutoFillForWorkspace`/commit split so the parts worth unit-testing are separated from the part that needs a live Temporal connection this step's own tests don't exercise (the same established boundary STEP 12 drew around `apps/web`'s render/publish triggers).
9. **A proactive fix, not a reactive one: `createUgcConceptAndStoryboard` validates `brandProfileId` ownership before use** — the exact class of gap STEP 14 found and fixed reactively in `generateConceptsForWorkspace` (an unvalidated `brandProfileId` accepted from caller input). Built correctly the first time here rather than left for a future step to discover.
10. **`apps/web` gained its THIRD real DB-integration test this build** (`ugc-service.test.ts`), extending the same generic-`db`-parameter pattern STEP 13/14 established, this time proving all three of GATE 15's own literal claims against real seeded workspace data rather than only unit-level pure-function behaviour.

## What was built

### `packages/db`
`consent_artefacts` table (migration 0017, real RLS block); `personas` gained `models_real_person` and a real `consent_artefact_id` FK, replacing the unused opaque `consent_artefact_ref` text column (dropped in the same migration).

### `packages/core/src/ugc`
`consent.ts` (`checkPersonaConsent`), `public-figure-check.ts` (`detectPublicFigureReference`, config schema + loader), `persona-policy.ts` (`checkPersonaGenerationPolicy`, scope decision 3's ordering), `clip-licensing.ts` (`isClipUsableFor`/`selectLicensedClip`), `identity-consistency.ts` (`scoreIdentityConsistency`). 34 tests across all five modules, including a public-figure config validation test against the real `config/public-figures.json` file and an identity-consistency test using real synthetic bitmaps through the real `perceptualHash`/`hammingDistance` functions.

### `config/public-figures.json`
The real, explicitly-labelled illustrative seed list (scope decision 5).

### `apps/web`
`ugc-service.ts` — persona CRUD, consent-artefact CRUD, `moderation_reviews` reader/writer (scope decision 4), `checkPersonaPolicyForGeneration` (wires the pure policy function to real DB rows), `selectUsableClipForWorkspace`, `computeIdentityConsistencyReportForPersona`, `createUgcConceptAndStoryboard`/`triggerUgcBatchGeneration` (scope decision 8). `routers/ugc.ts` — the full tRPC surface (`personas`, `consentArtefacts`, `policy.check`, `moderationReviews.request/resolve`, `clips.selectUsable`, `identityConsistency.report`, `batch.generate`), wired into `routers/_app.ts`. A real, functional (not maximally polished — consistent with the established precedent for less-central surfaces) UGC Studio UI at `app/ugc`: a persona library with a visible "NO CONSENT ON FILE" badge for any real-person persona missing one, a live policy-check button that calls the same pure check the batch endpoint runs server-side before ever creating a render, and a batch-generation form. 14 tests in `server/__tests__/ugc-service.test.ts` proving all three GATE 15 claims plus the consent gate, the moderation-review unlock flow (approved vs. rejected), and workspace-scoping on personas/consent artefacts/clips/reviews.

### `scripts/gate-15`
Real orchestrator — runs `packages/core`'s ugc suite and apps/web's ugc-service test directly. Run `pnpm gate:15` for the live report.

## What this step does not do

No funded, real video-generation vendor to verify identity-consistency scoring against actual photorealistic output — the scoring mechanism is real and tested; its application to real vendor renders is unverified for the same funded-credential reason as every other vendor-dependent claim in this build. No licensed public-figure/celebrity database (scope decision 5) — a real NER service or licensed data source is a genuine follow-up. No cryptographic verification of a consent artefact's authenticity — `consent_artefacts` records that a document was uploaded and optionally verified by a staff member (`verifiedByUserId`), which is procedural, not cryptographic; a real e-signature/notarization integration is out of scope here. `triggerUgcBatchGeneration`'s Temporal-dependent half is not PGlite/Temporal-integration-tested in this step (scope decision 8) — the same established boundary prior steps already draw around `apps/web`'s render-trigger call sites. No UI for a platform moderator to actually resolve a review (the `moderationReviews.resolve` endpoint is real and tested; a moderator-facing admin screen for it is not built — the same "endpoint real, admin UI deferred" scope trim used elsewhere in this build).
