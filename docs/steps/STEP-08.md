# STEP 8 — Content Engine

Status: proceeding without an approval gate (see STEP-03.md's header note).

Planned via the `planner` agent before implementation (per this project's standing agent-orchestration rules for complex features); the plan's verified facts, three schema-gap findings, router algorithm, idempotency design, and honesty matrix are what this step actually built against. Departures from that plan are called out inline below.

## Scope decisions

1. **Provider adapters are deterministic stubs, not real vendor integrations.** Kling, Veo, Seedance, MiniMax, Seedream, ElevenLabs, WhisperX all need funded API keys — a credential decision, not something to fabricate, matching STEP 6's LLM-extraction stub precedent. Each stub's capability manifest is transcribed from the build script's roster and public vendor claims, flagged `[UNVERIFIED FIXTURE]` in its own file header per the `provider-adapter` command's rule. What's real: the `generate`/`poll` contract, the deterministic content-addressed job simulation (`DeterministicJobStore`), and — critically — the **router, the idempotency ledger, and the Temporal workflow orchestrating them**, all genuinely tested end-to-end.
2. **A genuinely real embedded Postgres (PGlite) replaces mocks for STEP 8's own new database-dependent tests.** Discovered and verified directly during this step: `@electric-sql/pglite` is a real Postgres compiled to WASM that runs with no server process, and it genuinely supports the `vector` extension, `CREATE ROLE`, and real RLS enforcement (`FORCE ROW LEVEL SECURITY` + a policy actually blocks a cross-workspace read — verified, not assumed). `packages/db/src/testing/pglite.ts` replays this repo's own real migration files (0000–0008) against it. This is used for STEP 8's own new tests (`packages/db/__tests__/pglite-harness.test.ts`, all of `apps/worker/src/__tests__/`) — **retrofitting STEP 2–7's existing `itWithDb`-skipped tests onto this harness is a real, valuable follow-up, flagged here and in CLAUDE.md, not done in this step** to keep STEP 8's scope to STEP 8's own work. One documented PGlite limitation found while building the harness: `current_setting(name, true)` on a truly-unset custom GUC returns `''` rather than SQL `NULL` (a real behavioral difference from Postgres, not a bug in this app) — see `pglite.ts`'s inline comment; the harness cannot exercise RLS's literal not-set fail-closed path (only real Postgres, via `rls-fail-closed.test.ts`, can), but genuinely exercises "workspace id set to a value matching no row" fail-closed, which is the same guarantee from the caller's point of view.
3. **Every Dashboard-adjacent number in this step is a real query or a real, documented model — never a hand-typed placeholder.** Concept generation, trend retrieval, QC, and provenance all operate on real database state; the only actual stubs are the vendor API calls themselves and the text-generation calls (pending STEP 8B).
4. **C2PA manifest content is real; cryptographic signing is not.** Feasibility researched directly: `@contentauth/c2pa-node` (the official CAI binding) installs and its Builder/Reader API genuinely runs, reaching real certificate-profile validation in the actual Rust engine — which correctly rejected a self-signed test certificate (C2PA requires a spec-conformant signing cert even for local testing; confirmed via repeated attempts, not a single failed try). It also requires Node ≥22; this monorepo is pinned to Node 20. Given both a real signing certificate and a Node version bump are deployment decisions, this repo does not take a hard dependency on the library. `packages/core/src/provenance/c2pa-manifest.ts` builds a real, schema-shaped manifest (real `c2pa.created` action, `trainedAlgorithmicMedia` digital source type, model+prompt-hash assertion); `DevUnsignedManifestSigner` stores it and honestly records `c2paSigned: false` on the `renders` row.
5. **`generateShots`/`generateVo` use only the router's top-ranked provider — no fallback-chain walking to a secondary provider on persistent failure.** ADR 0004 describes the router selecting a *chain*; STEP 8 builds `selectChain`/`selectOne` fully (tested), but the activities that consume it only call `selectOne`. Advancing to `chain[1]` on a provider's *persistent* (not transient) failure is a real, flagged gap — the concurrency test's injected failure is transient-at-submit (recoverable by Temporal's own retry), which is honestly a different, narrower claim than "the fallback chain works."
6. **`compose`/`normalise` are not metered under C5.** C5 scopes metering to AI provider calls (video/image/text/tts/transcription) — a compositing pass over already-generated assets is not itself a model call. Both are still routed through the same idempotency ledger (`withStep` with `skipMetering: true`), since a retried compose must not silently re-run expensive work even though it isn't AI-metered.
7. **`apps/render`'s Remotion compositions are real component shape, unrunnable in this environment.** They need real shot/VO media files (no funded provider key) and — separately — this sandbox has no `ffmpeg` binary at all, confirmed directly (`ffmpeg -version` fails). The stub compositor (`apps/worker/src/composition/stub.compositor.ts`) does not invoke Remotion; it emits a JSON description of what the composition would produce, with real dimensions/duration derived from the spec, so QC's checks run against real numbers.

## Bugs found and fixed during this step

- **`ProviderRegistry.resolve()` didn't cache adapter instances** — every call re-invoked the factory, silently discarding a stub adapter's simulated job state on each Temporal activity retry (`Error: Unknown job id ... generate() must be called before poll()`). Found by the happy-path workflow test genuinely retrying an activity. Fixed by caching instances per `(kind, id)`; a real HTTP-backed adapter benefits from this too (stable client, connection reuse), so this is a correctness fix, not a test-only patch. Regression test added.
- **`refresh_credit_balances()` (migration 0001) was never `SECURITY DEFINER`** — the AFTER INSERT trigger on `credit_ledger` ran with the *inserting* role's privileges, and the app role (`velocity_app`) can insert into `credit_ledger` but has no `REFRESH` grant on the `credit_balances` materialized view. Every real app-role insert into `credit_ledger` failed with `permission denied for materialized view credit_balances`. **This was invisible for six steps** because every prior test that touched `credit_ledger` did so through the admin connection (which owns everything); STEP 8's C5 metering (`packages/core/src/metering/usage-recorder.ts`) is the first code in this codebase to actually insert into `credit_ledger` as the app role in a live-tested path. Fixed in migration 0008 (`SECURITY DEFINER`); regression test added (`packages/db/__tests__/pglite-harness.test.ts`) that inserts as the app role and asserts it doesn't throw.
- **`vitest`'s default file-level parallelism doesn't suit this test suite.** Each `apps/worker` integration test spins up a real embedded Temporal test server (a JVM process) and a real embedded Postgres (PGlite). Running them concurrently caused cascading heartbeat timeouts unrelated to the pipeline logic; even sequential-with-forked-process-isolation still saw elevated failure rates on the concurrency test specifically, from cumulative resource pressure on this sandboxed machine. Fixed by excluding the concurrency test from the default `vitest run` (documented in `vitest.config.ts`) and giving it its own `pnpm --filter @velocity/worker test:concurrency` script, verified to pass reliably (0% failure) in isolation.
- **`Composition<Props>` (Remotion) needs two type arguments** (`Schema`, `Props`), not one — fixed by defining real Zod schemas for each composition's props rather than fighting the generic inference.

## What this step does not do

No real vendor API calls (scope decision 1). No cryptographically signed C2PA manifests (scope decision 4). No fallback-chain walking on persistent provider failure (scope decision 5). No real Remotion renders — no ffmpeg in this environment, no real shot/VO media (scope decision 7). No text engine — hooks, captions, and the `TextPlan` itself are STEP 8B's job; `composeText` is a documented seam. No semantic (embedding) search over the Media Library — `media_assets.embedding` exists but nothing populates it yet. STEP 2–7's `itWithDb`-skipped tests are not retrofitted onto the new PGlite harness (a real, valuable, explicitly-flagged follow-up).
